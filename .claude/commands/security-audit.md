ultrathink を適用し、このプロジェクトの包括的なセキュリティ監査と依存関係の更新計画を作成してください。

ステップ1: `requirements.txt` と `.github/workflows/daily.yml` の `pip install` 行を読み、バージョン未固定・古い・既知の CVE がある依存関係を特定してください。2つのリストのずれも指摘してください。

ステップ2: OWASP Top 10 の観点で、このコードベース特有のリスクを攻撃者の視点でスキャンしてください。特に次を確認すること:
- LLM が生成したテキストを無害化せずに HTML 化している箇所（`src/static_publisher.py`）の XSS
- `.env`・API キー・WordPress / note.com 認証情報の扱い（ログ出力やコミットへの混入）
- GitHub Actions の権限（`contents: write`）と secrets の扱い
- 外部の RSS / Web から取り込むデータ（`src/traffic/trend_analyzer.py` など）経由のプロンプトインジェクション

ステップ3: 発見事項をマークダウンのレポートにまとめてください。各項目に「現在の状態」「推奨アクション」「破壊的変更のリスクレベル」を含めること。

ステップ4: レポートを出したら、修正に移ってよいか私に確認してください。許可が出た項目だけ、1件ずつ修正してください。API 課金や外部投稿が発生するスクリプトは実行しないこと。
